# React 핵심 개념 요약

## 1. ref로 값 참조하기

`useRef`는 렌더링에 영향을 주지 않는 값을 저장할 때 사용한다. state와 달리 변경해도 리렌더링이 발생하지 않는다. 타이머 ID, DOM 노드 등 "기억은 해야 하지만 화면엔 안 보여도 되는" 값에 적합하다.

---

## 2. ref로 DOM 조작하기

`ref={myRef}`로 DOM 노드에 직접 접근할 수 있다. 포커스, 스크롤, 크기 측정 등 React가 관리하지 않는 DOM 작업에 사용한다. `forwardRef`로 자식 컴포넌트의 DOM을 부모에게 노출할 수 있다.

---

## 3. Effect와 동기화하기

`useEffect`는 컴포넌트를 외부 시스템(네트워크, DOM, 타이머 등)과 동기화하는 탈출구다. 렌더링 후 실행되며, 반환하는 정리 함수(cleanup)는 다음 실행 전 또는 언마운트 시 호출된다.

---

## 4. Effect가 필요하지 않을 수도 있습니다

렌더링 중 계산 가능한 값, 이벤트 핸들러 내 로직, 부모에게 상태 전달은 Effect가 필요하지 않다. Effect는 **외부 시스템 동기화**에만 써야 한다. 불필요한 Effect는 코드를 복잡하게 만들고 성능을 저하시킨다.

---

## 5. 반응형 Effect의 생명주기

Effect는 "동기화 시작 → 동기화 중지"의 반복이다. 컴포넌트 생명주기(마운트/언마운트)가 아닌 **동기화 관점**으로 사고해야 한다. 의존성 배열은 Effect가 반응해야 할 반응형 값(reactive value)을 모두 포함해야 한다.

---

## 6. 이벤트와 Effect 분리하기

이벤트 핸들러는 특정 상호작용에, Effect는 동기화에 사용한다. `useEffectEvent`로 Effect 내에서 최신 값을 읽되 반응은 하지 않는 비반응형 로직을 분리할 수 있다.

---

## 7. Effect 의존성 제거하기

의존성을 줄이려면 코드를 변경해야 한다(린터를 억제하면 안 된다). 값이 진짜 반응형인지 확인하고, 필요 없으면 컴포넌트 외부로 이동하거나 Effect 내부로 옮긴다. 객체/함수 의존성은 원시값으로 추출해 해결한다.

---

## 8. 커스텀 Hook으로 로직 재사용하기

`use`로 시작하는 함수로 상태 로직을 추출해 여러 컴포넌트에서 재사용한다. 상태 자체는 공유되지 않고 **로직만 공유**된다. 커스텀 Hook은 컴포넌트를 선언적으로 만들고, 미래의 API 변경에 유연하게 대응할 수 있게 해준다.
